# D4 GROWBOOK 学習入口プロトタイプ 実装計画書

更新日: 2026-09-13（JST）
版: 0.5／独力解答→記録確認→終了後の音声対話へ訂正
対応要件: [D3](D3_学習入口プロトタイプ_要件定義書.md)

## 1. 採用案と訂正

**解答中は記録のみ。音声AIの接続と応答は解答終了後に開始する。**
旧版の「解答中から常時会話・ヒント提供」はユーザーの意図と異なるため撤回する。A段階から本物のリアルタイム音声を使う対象は、終了後の振り返りである。

名称はGROWBOOK。既存リポジトリの英語モックを維持し、英語の記録・振り返り入口を tutor/ に追加する。初回はNode.js標準HTTPサーバーとHTML/CSS/JavaScriptで実装し、当初のVite/React/Express案は採用しない。起動用の追加依存を不要にする。

## 2. 処理の順序

```text
生徒が黙って解く
  ├─ 画面録画・ローカル音声録音
  ├─ 問題ID付きの時刻付き静止画
  └─ 選択・選び直し・表示/非表示の操作ログ
        ↓ 解答終了
サーバー採点 + Responsesによる静止画/操作の観察メモ
        ↓
Realtime音声AIが最初の質問
        ↔ 生徒の説明で補完・訂正
        ↓ 本人が提案を承認
教科書の説明案・類題生成 → JSONと記録の引き渡し
```

動画ファイル全体をリアルタイムモデルに渡す構成ではない。録画ストリームの静止画と操作履歴で初期実装する。静止画では見えていない時間の挙動を推測で観測済みにしない。

  tutor/style.css            PC/iPad/スマホ幅の画面

## 4. 状態と音声

| 状態 | 動作 | AIの声 |
| --- | --- | --- |
| idle | 同意・開始待ち | なし |
| preparing | 画面共有・マイクの許可、記録開始 | なし |
| solving | 独力解答、録画、静止画、操作記録 | 接続しない |
| reviewing準備 | 解答確定、採点、記録解析 | 解析待ちを表示 |
| reviewing | AIから一問、本人の説明を聞いて補完 | 双方向リアルタイム |
| ended | 全トラック停止、保存・出力 | なし |

解答中の文字入力と音声接続ボタンを無効にする。解答前に教科書の正解へ誘導しない。許可待ちを各問題の表示時間へ含めない。終了・解答確定の多重実行を抑止する。

マイクは解答中にローカル録音するが、Realtimeへ送信するのは終了後。振り返り開始時は録音中のマイクを再利用する。AI音声は別ストリームとして録音する。

## 5. 観測と記録

問題は指定英語サイトの先頭3問。IDはeng-q1/eng-q2/eng-q3、元番号・表示順は1/2/3。選択肢IDは表示のA/B/Cと分離し、正解はサーバーだけが持つ。未回答の採点はnull。

MediaRecorderのMIME対応を実行時判定し、2秒ごとのチャンクをIndexedDBへ保存する。同じ録画器のチャンクを終了後に結合し、自分の声・AI音声・画面の各ファイルを出力する。録画停止・許可拒否は状態を分け、成功表示をしない。

静止画は最大960px、3秒以上の間隔、1セッション最大30枚。問題変更・解答変更・10秒間隔で採取し、時刻、問題ID、採取理由を保持する。終了後は各問題の先頭・中間・末尾から最大9枚を観察APIへ送る。

操作ログには選択変更の前後、問題を開いた時刻、ページの非表示を残す。操作のない区間と「分からなくて止まった」は別物。表示時間から非表示時間を分け、本人の説明がない段階では原因を決めつけない。

## 6. API

| パス | 用途 |
| --- | --- |
| GET /api/tutor/health | キーの設定有無とモデル名。キーそのものは返さない |
| GET /api/tutor/questions | 正解を含まない問題 |
| POST /api/tutor/grade | サーバーで正誤を確定 |
| POST /api/tutor/observe | 静止画・操作・採点から観察事実と確認質問を作る |
| POST /api/tutor/realtime/session | SDP交換。終了後の音声セッションを接続 |
| POST /api/tutor/chat | 振り返りの文字入力代替 |
| POST /api/tutor/action | 承認済みの教科書説明案・類題を生成 |

サーバーはlocalhost限定。別Origin、未知の問題/選択肢、不正画像、過大な入力を拒否する。利用頻度を制限し、外部APIエラーの生本文を返さない。APIキーはserver/.envから読み、クレジット不足と未設定を明示する。

## 7. 終了後の会話

1. 最終回答を固定し、採点する。
2. 観察APIへ実際のフレームとログを送る。失敗したら操作ログのみと明示する。
3. WebRTCを接続。観察メモ、採点、問題の表示順、操作履歴を文脈に加える。
4. Realtimeにresponse.createを一度送り、AIから最初の質問を行う。
5. 以後はVADのcreate_response/interrupt_responseを有効にし、自然な会話と割り込みを行う。
6. 本人の発言を同じセッションに保存。推測を否定されたら訂正し、記録上の正誤は保持する。
7. 本人の説明後にだけ教材案を提案。承認を受けて生成する。

指示例:
> 生徒は黙って解答を終えています。記録した静止画と選び直し、採点から、本人に確認したいことを一つだけ自然に聞いてください。長い停止だけでつまずきと断定せず、根拠が弱ければ「分からないところはあった？」でよいです。説明を聞き、観測と本人の理由を結びつけてください。

画像なしの場面を「見た」と言わない。生徒が聞いていない生成字幕を理解の証拠にしない。音声字幕の誤り・本人の訂正を区別する。

## 8. 教材への接続

AIのpropose_learning_actionで、説明案・類題・記録の提案カードを作る。関数の戻り値は「承認待ち」であり、生成完了ではない。

カード承認後に、観察メモ、問題/段落ID、本人の会話、正誤をResponsesへ渡す。同一リポジトリ内の英語教科書画面へ追加し、元の英語画面は上書きしない。生成内容は学習者に合う説明案として表示し、検証済み教科書とは称しない。

後続チームにはセッションJSONを渡す。現在のJSONは記録と会話を保持する初期形式で、理解状態の厳密なスキーマ検証・本人確認済み要約を自動確定する最終版は追加実装扱いとする。

## 9. 検証順序

1. 採点・未知ID・未回答・秘密ファイル非公開・Origin拒否を自動テスト。
2. 模擬APIで観察・教材生成・残高不足・Realtime設定の契約をテスト。実通信と明確に分ける。
3. ブラウザで開始、3問選択、選び直し、終了、記録表示を確認。
4. 解答中にAIへ接続していないことを確認。
5. 記録画像が終了後に送られ、実AIの確認質問に反映されることを確認。
6. 実マイクと画面共有で録音・録画・音声往復・割り込みを確認。
7. 教科書の提案承認、実生成、保存ファイルを確認。
8. GitHub書き込み権限を確認して自分のファイルだけをコミット・pushする。

## 10. 起動・配布・未完了の区別

Node.js 22以上。server/.envを設定してnpm start。PCで http://localhost:3000/tutor/ を開く。追加の実行依存は不要。

GitHub Pagesは静的プレビューのみ。実音声を遠隔公開するにはHTTPSバックエンド・認証・利用上限が別途必要で、当日のローカルデモと混同しない。

現状: APIクレジット追加後のResponses実応答を確認済み。実装を訂正中。実マイク/画面収録の最終試験とGitHubへのpush完了は、実測できるまで未完了と記載する。iPad実機、途中再開、長時間耐久、音声と映像の完全同期は未検証。
