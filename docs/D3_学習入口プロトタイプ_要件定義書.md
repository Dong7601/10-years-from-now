# D3 GROWBOOK 学習入口プロトタイプ 要件定義書

作成・更新日: 2026-09-13（JST）
版: 0.5／ユーザーによる体験の訂正と正式名称を反映
関連: [実装計画書](D4_学習入口プロトタイプ_実装計画書.md)／英語問題の参照元: https://manabiai.netlify.app/

## 1. 作るものと完成条件

**生徒は黙って問題を解く。その間を録画・録音・操作記録する。解答終了後、AIがその記録を手掛かりに音声で話しかけ、生徒の説明で情報を補完する。**

完成条件は「独力で解答 → 解答過程を記録 → 終了後にAIが自然に問いかける → 生徒が人間と話すように返す → 記録と説明を結びつける → 本人に合う教材の提案へつなぐ」が通ること。

例えば、選び直しが記録されていれば「第3問で選び直していたけど、どう考えていた？」と聞く。根拠が弱ければ「分からないところはあった？」でよい。「止まっていた＝つまずいていた」と決めつけない。本人が「離席していた」と話したら時間の解釈を訂正するが、記録上の誤答は消さない。

**「A段階でリアルタイム音声」は、終了後の振り返りを本物の双方向音声にするという意味。旧版の「解答中から質問・ヒントを返す」は私の誤解であり撤回する。** 解答中にAIが挨拶・質問・解説・提案を出すことは必須範囲ではなく、今回の標準体験では行わない。

名称は **GROWBOOK**。既存の英語参考画面は残し、まず英語の記録・振り返り入口から同一リポジトリ内の教科書更新案へ接続する。

## 2. 対象範囲

| 項目 | 決定・方針 |
| --- | --- |
| 対象 | 生徒の学習入口、記録、終了後の音声振り返り、教材への引き渡し |
| 題材 | 指定サイト https://manabiai.netlify.app/ の英語・関係詞／時制／語彙 |
| 初回問題 | 指定サイトの先頭3問。eng-q1 / eng-q2 / eng-q3、元の問題番号は1 / 2 / 3 |
| 当日デモ | PC Chrome・マイク・ローカルNodeサーバー |
| iPad | 問題画面と音声は候補。ブラウザ画面録画は非対応なので同等完成と扱わない |
| 公開 | GitHubへソースをアップロード。GitHub Pagesは静的プレビューのみ |
| API | OpenAI APIキーは server/.env にのみ置く。ブラウザへ渡さない |

D1/D2や全体のstate.mdは上書きしない。本書と異なる旧前提は入口担当について本書を優先する。

## 3. 学習の流れ

1. 記録・AIへの送信の説明を読み、同意する。個人情報のない学習画面を共有する。
2. マイク・画面記録の成否を表示。許可待ちは問題の解答時間に含めない。
3. 生徒が静かに3問を解く。AIの音声接続・会話は開始しない。
4. 問題の表示、選択、選び直し、非表示、経過時間、録画フレームを共通の時刻で記録する。
5. 解答終了で回答を確定し、採点する。記録を解析し「観測事実」と「本人に確認したいこと」を作る。
6. AIが音声で最初の質問を一つだけ行う。生徒は毎回ボタンを押さずに返答できる。割り込みにも対応する。
7. 本人の説明で仮説を補完・訂正する。誤答・長時間・本人の説明を別々に保持する。
8. 話を聞いてから、教科書の説明変更や類題を提案する。カードの承認後だけ生成・表示する。
9. 学習終了で記録を止め、会話・観測・提案を含むJSONと、録音・録画ファイルを保存する。

## 4. A段階の必須機能

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F01 | 同意・能力検出・許可状態の表示 | 録画できていないのに記録中と表示しない |
| F02 | 独力での問題演習 | 解答中のAI発話・質問入力・ヒント・教材提案が無効 |
| F03 | 選択・選び直しの履歴 | 元問題ID、表示順、時刻、旧選択、新選択が残る |
| F04 | 時間の観測 | 表示時間と非表示時間を分け、停止理由を断定しない |
| F05 | 画面と音声の記録 | 開始から終了まで実記録。欠落・拒否を区別 |
| F06 | 録画情報のAI利用 | 実際のフレームと時刻を操作ログに対応づける。画像未提供なら見たと言わない |
| F07 | 正誤判定 | サーバー側で採点。未回答は null |
| F08 | 終了後のリアルタイム音声 | AIが先に話しかけ、自然な双方向会話・割り込みができる |
| F09 | 情報補完 | 本人の説明が記録に追加され、否定された仮説を断定しない |
| F10 | 提案と承認 | 本人の説明前に教材を決めつけない。承認前に生成済みと言わない |
| F11 | 教材連携 | 科目、問題、段落、観測、会話、生成案を同じセッションで受け渡す |
| F12 | 記録出力・停止 | マイク・画面を停止し、JSONとメディアを別々にダウンロードできる |

録画なし・音声なしの縮退モードは利用できるが、A段階の完全合格とは区別する。APIエラー時の固定返答を「実AI」と表示しない。

## 5. 録画理解の実装上の意味

当日の初期実装は、録画ストリームから時刻付き静止画を採取し、終了後にAIで解析する。動画全体を連続入力するわけではない。問題変更・解答変更・定期採取の画像を、問題IDと操作時刻に対応づける。

このため、静止画の間に起きた全ての動作や細かな手の動きを理解したとは主張しない。画面内の選択や変化は操作ログで補う。将来的に保存動画から停止前後の短い区間を追加抽出できるが、当日の完成範囲には含めない。

録画ファイルを保存することと、AIがその内容を参照できることは別々に検証する。

## 6. 対話と教材引き渡し

観測、仮説、本人の説明を混ぜない。

- 観測: 第1問でwhatを選択し、その後にthatへ選び直した。
- 未確認の可能性: 先行詞がある文でwhatとthatの使い分けに迷ったのかもしれない。
- 確認質問: 「選び直したとき、何を考えていた？」
- 本人の説明: 「whatは『何』だから、本が何を変えたかを表せると思った」。
- 提案: 本人の説明を踏まえ、thatとwhatの違いを例文で示す説明案を生成する。

停止時間だけを根拠に弱点ラベルを確定しない。質問は一度に一つ。3往復程度を目安にし、本人が終了できるようにする。

参照画面: [GROWBOOKの既存モック](https://manabiai.netlify.app/)。
既存サイトにはGeminiチャットAPIがあるが、記録コンテキストを取り込むAPIは未確認のため、同じリポジトリの英語教科書画面へ接続する。参考URLを開くだけでコンテキストが渡るとは扱わない。

## 7. データと保護

記録は sessionId、問題ID、表示順、時刻で関連づける。JSONには回答・操作・観察メモ・会話・提案の承認／却下・生成結果・メディア一覧を含める。録音は自分とAIを区別する。

キーはGit除外し、公開ビルドは許可した静的ファイルだけに限定する。端末保存とAPIへの送信は同意説明で区別する。プロトタイプはローカル限定で、実在の生徒での運用は同意・保存期間・認証等を整備してから行う。

API側のデータ保持全体がゼロであるとは保証しない。音声字幕には認識誤りや割り込み時の未再生文が含まれ得るため、それだけを「本人が聞いた／理解した」証拠にしない。

## 8. 検証と到達状況

必須の実演は「黙って解答している間にAIが話さない」「実記録が残る」「終了後の第一声が実際の記録を踏まえる」「本人の訂正が後続説明に反映される」の4点。

APIクレジット追加後、Responsesの実応答は確認済み。ローカル実装は進行中であり、実マイク・画面共有・音声往復の最終検証、GitHubへのpushはそれぞれ別途結果を記録する。設計書の記述だけで完成としない。
